## Scope

Add a versioned image request and response contract. Keep LiteLLM as the default backend. Reserve Codex CLI and Claude Code identities in version 1.
Keep legacy profiles, prompts, dynamic schemas, and caller validation.
Do not change chat, Homebox data, dependencies, or published QA.
Two keyless test backends will prove that readiness does not require an API key for every backend.

## Milestones

1. Add the contract, typed errors, backend interface, and JSON examples.
2. Adapt the existing LiteLLM vision path and add backend-specific readiness checks.
3. Test legacy settings, detect/analyze/correct, custom fields, keyless execution, errors, and resource limits.
4. Run repository checks and browser checks where behavior is visible. Complete all six review passes.
5. Publish one PR, verify its CI, merge, verify main CI, and close the issue and Project item.

## Compatibility and recovery

Existing installations select LiteLLM without a new setting. Existing JSON repair and Router fallback remain in use.
The worker is a later task. This change adds no endpoint that can run a command or write inventory.
Revert the PR to restore the previous vision path. No data migration is required.

The current connection plan includes both official CLIs. Real worker execution is AI03; profile UI is AI04.
