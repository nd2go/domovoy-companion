## Six review passes

Review scope: the base above through the runtime commit, then the added acceptance tests and this record.

1. **Logic and contracts:** traced profile selection, frozen API credentials, worker context, final schema validation, and browser confirmation through Homebox reads.
2. **Edge cases:** checked stale revisions, empty models, legacy profiles, cross-context cancellation, timeout, disconnect cleanup, replacement failure, and retry. Added missing context and admission recovery tests.
3. **Tests:** inspected assertions and ran unit, browser, and complete CI live selections. Real CLI checks above are separate from mocked failure coverage.
4. **Security and abuse:** completed the input paths below. No unresolved confirmed high or critical finding was found in this change.
5. **CPU and memory:** traced JSON/image copies, one CLI admission slot, bounded streams, cache replacement, task cleanup, and sequential browser processing. Peak memory and CPU were not benchmarked.
6. **Readability and language:** checked new control flow, names, comments, and developer prose. The official STE Issue 9 PDF returned HTTP 403. The full dictionary check is incomplete; full STE conformity is not claimed.

### External input and resource evidence

| Input path | Controls and evidence |
| --- | --- |
| Browser auth, collection, and draft headers to worker | Existing Homebox identity verification plus live `/groups` access check; strict UUIDs and bounded revision. Negative tests reject a foreign collection and altered returned context. UUIDs do not authorize access. |
| Cancel request to active operation | Verified owner, collection, request UUID, draft UUID, and revision must all match. A foreign-owner test fails to cancel. Real browser cancellation retains the draft and permits retry. |
| Profile CRUD and stored settings | Backend and status enums, API-only fallback, atomic file replacement, mode 0600 temporary file. Tests preserve old data and reject invalid fallback before saving. |
| Uploads to image processing | Existing streamed request and per-file byte limits remain. CLI admission precedes multipart parsing; the second body is not read when busy. Existing Pillow decode controls remain. Full concurrent peak memory was not measured. |
| Vision payload to host | Existing AI02 limits: 30 images, 20 MiB per image, 40 MiB total, 64 KiB schema, 64 KiB prompt fields, depth and element bounds. Worker payload is capped at 57 MiB. Checksums cover sent images. |
| Worker URL and credential | Server-only configuration; HTTP loopback or Docker host allowlist; no redirects or environment proxies. The payload contains no API key. Tests assert transport settings and credential exclusion. |
| Worker response to JSON and Pydantic | Readiness/cancel limit 64 KiB; result envelope limit 2 MiB plus 64 KiB, checked while streaming. Encoded responses are rejected. Context, request ID, backend, version, and final strict field types are checked. |
| Model call and cost | One admitted CLI request per Companion process and one model process enforced by the existing worker. Total budget defaults to 120 seconds, capped at 300. Browser adds 15 seconds for transport. No CLI queue, auto retry, or API fallback. |
| Model output to inventory | The model returns data only. Existing browser review and explicit submit remain. Independent reads confirm persisted values and attachments. Chat model requests are rejected in CLI mode. |

No new shell execution, template execution, public worker endpoint, or production dependency was added.
The review does not prove the absence of all vulnerabilities or performance limits.
